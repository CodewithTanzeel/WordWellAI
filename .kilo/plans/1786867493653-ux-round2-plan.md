# UX Improvement Plan — Round 2

Six items from the UX review, scoped to small, safe edits. No new components, no token changes, no CrisisView chrome changes.

---

## C1 — Session continuity hook

**What:** Show "Last check-in: [relative time]" above the textarea when a previous timestamp exists.

**Implementation:**
- `App.tsx` — on successful submit (`handleSubmit` try-block, after `setResult`), write `localStorage.setItem("sift-last-checkin", new Date().toISOString())`.
- `JournalForm.tsx` — add optional `lastCheckIn?: string` prop. When present, render a `font-pixel text-[11px] text-[color:var(--muted)]` line above the textarea label: `Last check-in: [relative time]`. Format with `Intl.RelativeTimeFormat` or a simple "X min/hr/day ago" helper — keep it sentence-case.
- Relative-time helper: < 60s → "just now", < 60min → "X min ago", < 24h → "X hr ago", else → date string like "Aug 15". No external lib.

**Effect:** Gives the user a reason to return. The app stops feeling like a one-shot and starts feeling like a practice. No content stored in localStorage — only the timestamp, avoiding privacy risk in a mental-health context.

**Edge cases:**
- First visit (no key) → line doesn't render.
- "NEW CHECK-IN" does NOT clear the timestamp — the next visit still shows the previous submission time, which is correct (the timestamp reflects last actual submit, not last form clear).

## C2 — Textarea auto-grow + keyboard submit shortcut

**What:** Let the textarea grow with content (up to a cap) and allow Ctrl+Enter / Cmd+Enter to submit.

**Implementation:**
- `JournalForm.tsx` — change `rows={4}` to `rows={Math.min(8, Math.max(4, Math.ceil(value.length / 80)))}`. Grows one row per ~80 chars, floor 4, ceiling 8. Remove `sm:min-h-40` (rows now handles sizing at all breakpoints; the class was a workaround for the old fixed `rows={6}`).
- Add `onKeyDown` handler: if `(e.ctrlKey || e.metaKey) && e.key === "Enter"` and `canSubmit`, call `onSubmit(value)`. Don't prevent default on other keys.

**Effect:** Long reflections no longer require scrolling inside a cramped box. Keyboard users can submit without reaching for the button. The 8-row cap prevents the form from dominating the viewport.

## C3 — Disabled textarea cursor clarity

**What:** The textarea currently has `disabled:opacity-60` but no cursor change. The submit button has `disabled:cursor-not-allowed`; the textarea should match.

**Implementation:**
- `JournalForm.tsx` — add `disabled:cursor-not-allowed` to the textarea's className.

**Effect:** Removes the one remaining ambiguity in the submit flow — when the field is greyed out during a request, the cursor makes it explicit that input is blocked, not just styled.

## C5 — `prefers-contrast: more` edge case (no code change)

**What:** The global `prefers-reduced-motion` rule kills animation duration but leaves final static transforms in place (e.g., `eixyWait`'s `translateY(-3px)` at rest). Users with `prefers-contrast: more` may see a slight offset that looks like a layout glitch rather than an animation artifact.

**Decision:** No code change this round. The overlap is small (±3–4px) and only visible to users with both `prefers-reduced-motion` and `prefers-contrast: more` simultaneously — a rare combination. Flag in DESIGN_LOG as a known edge case. Fix if reported.

**Effect:** None. Documented limitation, no behavior change.
